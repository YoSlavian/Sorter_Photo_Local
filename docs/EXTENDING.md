# Расширение

Слои не знают друг о друге ничего, кроме структур на границе. Ниже — куда
добавлять, чтобы не трогать остальное.

## Новый язык описаний

Парсер не содержит слов ни одного языка: все маркеры лежат в
`src/bpmn_architect/parsing/lexicon.py`.

1. добавьте варианты в регулярные выражения маркеров (начало, конец, условие,
   альтернатива, параллелизм, слияние, возврат, ожидание);
2. пополните `ROLE_STEMS` названиями ролей;
3. при необходимости добавьте морфологию в `morphology.py` — или не добавляйте:
   без неё формулировки останутся как есть, что безопасно;
4. добавьте язык в `_ARM_LABELS` (метки веток) и в `_PHRASES` в
   `analysis/narrate.py` (обратное описание).

Логика парсера при этом не меняется.

## Новая формулировка в существующем языке

Только `lexicon.py`. Проверить — `bpmn-architect explain файл.txt`, закрепить —
тестом в `tests/test_nlp_parser.py`.

## Новый тип элемента BPMN

1. `domain/model.py` — значение в `NodeKind` (значение = имя XML-элемента);
2. `building/builder.py` — отображение из `ActivityType`/`EventTrigger`;
3. `parsing/dsl.py` — ключевое слово, если элемент нужен в DSL;
4. `rendering/svg.py` — глиф для предпросмотра;
5. `frontend/src/lib/elements.ts` — палитра и список альтернативных типов.

Рендер BPMN XML менять не нужно: он отображает `NodeKind.value` напрямую.

## Новое правило проверки

Функция в `validation/rules.py` и регистрация в кортеже `RULES`:

```python
def rule_no_lonely_lane(model: ProcessModel, diagnostics: Diagnostics) -> None:
    for lane in model.lanes:
        if not model.nodes_in_lane(lane.id):
            diagnostics.warning("W110", f"дорожка {lane.name!r} пуста", lane.id)
```

Уровни: `error` — файл структурно неверен; `warning` — валидно, но нарушает
конвенцию; `info` — стоит перечитать. Правило автоматически появляется и в CLI,
и во вкладке «Проверка».

## Другая стратегия компоновки

Реализуйте `run(model) -> Layout` и передайте свой движок в конвейер. Этапы
(`ranking`, `ordering`, `positioning`, `routing`) заменяются и по отдельности —
каждый лежит в своём модуле и тестируется отдельно.

## Новый формат выгрузки

Модуль в `rendering/`, принимающий `ProcessModel` и `Layout`. Дальше —
эндпоинт в `server/routes.py` и пункт меню в `frontend/src/components/Toolbar.tsx`.

## Новый провайдер модели

Класс с тремя членами — и всё:

```python
class MyProvider:
    name = "my-provider"

    def available(self) -> bool:
        return bool(self.config.api_key)

    def complete(self, system: str, user: str) -> str:
        ...  # вернуть ответ модели как текст
```

Зарегистрируйте его в `interpreters/providers/base.py::resolve_provider`.
Промпт, разбор ответа и повтор при ошибке провайдера не касаются — это уровнем
выше, в `interpreters/llm.py`.

SDK импортируйте **внутри метода**, а зависимость объявляйте как optional
extra: ядро обязано оставаться устанавливаемым без единой зависимости.

## Новый синтаксис на входе

Парсер, возвращающий `IRProcess`. Остальной конвейер не меняется — так в
проекте появился DSL рядом с естественным языком.

## Новый эндпоинт

Логику — в `server/service.py` (без импорта FastAPI), схемы — в
`server/schemas.py`, тонкую обёртку — в `server/routes.py`. Такое разделение
позволяет тестировать поведение без поднятия сервера.

## Чего делать не стоит

* Складывать логику в `routes.py` — она станет непроверяемой без HTTP.
* Хранить состояние диаграммы на сервере: API намеренно без состояния, диаграмма
  живёт у клиента, а вопросы пересчитываются из неё.
* Заводить свой формат обмена вместо BPMN XML — он один на весь стек, и это то,
  что позволяет схеме в любой момент уйти в другой редактор.
* Подменять правку модели «оверлеем» во фронтенде: всё, что меняет диаграмму,
  должно проходить через модель bpmn-js, иначе оно не попадёт ни в undo, ни в
  файл.
